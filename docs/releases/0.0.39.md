# ZIPP 0.0.39

A bugfix and performance release fixing native Python CLI raw stdout/stderr streaming past 64 KiB, eliminating quadratic string slicing/searching hotspots in the Python runtime (`html.parser`, `html2text`, `markdownify`), completing `textwrap` keyword support, and delivering further steady-state DOM and regex throughput gains in the JavaScript engine.

Thank you to [@codeandsolder](https://github.com/codeandsolder) for reporting issue #108 and sharing detailed v0.0.38 verification results and cross-CPU benchmarks on #99, #100, and #101 — your follow-up reports pinpointed both the raw stdout truncation bug and the next wave of Python and JS optimization opportunities.

## New in 0.0.39

- **Python CLI exact byte-for-byte stdout/stderr streaming (#108):**
  - Adds a dedicated raw streaming output sink (`ScriptState::set_raw_output_sink`) and native `__zipp_py_write` bridge so `zipp py` (file, directory, and stdin `-`) preserves exact UTF-8 and binary bytes with no spurious trailing newline (`print("hello", end="")`, `sys.stdout.write("hello")`) and streams arbitrarily long output past 64 KiB without `inspect_line`'s `"..."` truncation.
  - Adds `sys.stdout.buffer` / `sys.stderr.buffer` (`write`, `flush`), `writelines`, `flush=True`, `sys.stdout = None`, and `sys.stdout` redirection support while preserving explicit `output_limit` enforcement (failing loudly instead of silently truncating) on metered/sandboxed hosts.
- **Python HTML parsing, string, `re`, truthiness, and `textwrap` throughput (#100 follow-up):**
  - Eliminates O(N²) `codepoints(s)` splitting in Python string slicing (`s[i:j]`), bounded `str.find`/`rfind`/`index`/`rindex`/`count`, and bounded `str.startswith`/`endswith`, sharing an O(log K) surrogate-pair cache across `str` and `re` so both ASCII and astral-containing strings scale linearly.
  - Adds native ASCII step-1 slicing in `PyStrItem`, native bounded `PY_STRM` fast paths for `find`/`rfind`/`count`/`startswith`/`endswith`, per-class `R.truth` caching, broader `PyMethod` `gb` caching for dict-less builtin classes, and dict-less `re.Pattern`/`re.Match` objects with direct `c1`–`c4` fast paths.
  - Cuts a 75 KiB `html.parser` parse from `10.1 s` to `66.9 ms` (~151× faster), cuts `PyMethod` misses in `markdownify` + BeautifulSoup4 by 81.5%, and fixes `textwrap.wrap`/`fill`/`TextWrapper` keyword options (`break_long_words`, `subsequent_indent`, etc.) so unmodified `html2text` works out of the box with its default `body_width=78` and matches CPython byte-for-byte even past 64 KiB.
- **JavaScript `%RegExp.prototype%` fast-slot cache and planned object pooling (#101 follow-up):**
  - Registers `@@split` (`REGEXP_SYM_SPLIT`) in `REGEXP_PROTOCOL_PROTO_SLOTS`, fixing a missed cache fill that previously prevented `%RegExp.prototype%` fast-slot caching from activating on regex `replace`/`split`/`match`/`flags` calls.
  - Adds pooled, slab-backed `Heap::alloc_planned_object` for `NewPlannedObject` (JIT and interpreter) and empty-map guards in `jit_make_closure`, reducing steady-state profiler samples by ~12.4% on Defuddle and ~9.0% on WebforAI (with 55–72% less GC courier traffic) while keeping outputs byte-identical to Node.
