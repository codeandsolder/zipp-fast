# ZIPP 0.0.36

A fix release, with speed work in the interpreter and in loading scripts.
A minor garbage collection could free an object a program was still
using: a closure held by one of the first object literals a program built
was swept and its slot handed to something else. It happened in 0.0.33,
0.0.34 and 0.0.35 under `zipp js`, in the interpreter and, by default, in
large programs such as the bundled applications, which run without the
JIT. The loop runner, the interpreter's tier for hot loops, now takes ten
more kinds of operation, so loops that left it at their first `new`,
`super`, `in`, `instanceof`, `Object.keys` or `Array.isArray` stay in it.
Over 90 benchmark programs 0.0.36 takes 0.997x 0.0.35's time with the JIT
and is ahead of Node 24 on 70 of the 89 that Node runs (0.0.35: 71 in the
same runs); interpreted it takes 0.984x 0.0.35's time and is ahead of
`node --jitless` on 75 (0.0.35: 70). The bundled applications are within
3% of 0.0.35.

## Fixed in 0.0.36

- **A live closure could be swept.** The command line's Node-compatible
  runtime builds object literals of its own while it starts, and an object
  literal takes its object from a batch the heap makes ahead of time. When
  setup finished, the collector marked everything allocated so far as old,
  the batch's unused objects with them, while they stayed in the batch.
  The program's first object literals then took those objects: old objects
  whose first values, all young, were recorded nowhere a minor collection
  looks, so a minor collection could free what they held while they still
  held it. A Proxy whose handler was `{ ownKeys: function () { ... } }`,
  built early in a program, later threw "proxy handler's ownKeys trap is
  not a function": the slot held an array by then. 0.0.36 gives the batch
  up before setup's objects are marked old, as every collection does before
  it runs. With the nursery verifier on (`ZIPP_NURSERY_VERIFY=1`, which
  checks every minor collection against a full one), 0.0.35 reports a
  missed object on 16 of the 90 benchmark programs in the interpreter and
  on Babel, Prettier, the eight libraries and React server rendering by
  default; 0.0.36 on none. A new test runs the first literals of a program
  through 300,000 allocations under `zipp js` against Node's output, in the
  interpreter and by default, with and without the verifier.

## New in 0.0.36

- **The loop runner takes more of what loops do.** Every `new` sent a loop
  back to the dispatch loop; the runner now constructs with a plain
  constructor function and with a base class whose constructor has no
  field initializers, and pushes the constructor's frame itself. It also
  reads and writes through `super` (`class-prototype-hot`'s call loops
  never entered it), answers `i in array`, takes the computed key of
  `o[k] += v` and `o[k]++`, inverts a number (`~x`), and answers
  `Array.isArray`, `instanceof` and `Object.keys` in the cases their fast
  paths do; a property read no cache answers (a class instance's
  `constructor`, a function's own property) is finished in the runner
  instead of sending the loop out. An object literal's key plan is checked
  once per function rather than once per object. Interpreted,
  `sparse-array` takes 0.59x 0.0.35's time, `typedarray-math` 0.85x,
  `obj_literal` 0.89x, `new_class` 0.90x and `new_obj` 0.92x; the first
  three are now ahead of `node --jitless`.
- **`toUpperCase` and `toLowerCase` search less.** Mapping a non-ASCII
  character searched the whole table of case runs (186 or 303 entries);
  native builds now index the runs by 256-code-point page and search only
  those that reach the character's page. A program that upper- and
  lower-cases 13,172 characters of Latin, Greek and Cyrillic text 200 times
  takes 29.4 ms against 35.0 (plain builds of the two sources). The
  WebAssembly modules keep the plain search, which is smaller.
- **Loading a script does less.** The index of line starts that error
  positions use skips eight plain bytes at a time instead of reading one;
  a string literal with no escape is copied from the source in one step
  instead of being decoded into UTF-16 and encoded back; and an ASCII
  identifier is not checked as UTF-8 a second time. Loading Prettier's
  bundle runs 7% fewer instructions and Vue's 4%; on Windows, compiling
  Prettier, Babel and the eight libraries without running them takes 2 to
  5% less time (plain builds).
- **Dependencies:** wgpu 30.0.2 and bumpalo 3.20.4 in the engine; vite
  8.3.8, `@vitejs/plugin-react` 6.3.0 and `@cloudflare/vite-plugin` 1.69.1
  on the site.
- **CI:** the Python lane runs on Ubuntu 24.04. GitHub's `ubuntu-latest`
  moved to an image whose CPython (3.14) accepts syntax that ZIPP's Python
  3.13 front end does not yet parse (`except A, B:` without parentheses,
  template strings), and the front end's conformance check compares with
  the runner's own CPython.

## Performance

Measured on 17 November 2026 on native Windows x86-64 (Ryzen 9 9950X3D),
with no builds or test runs going: the published 0.0.35 Windows binary
against this release's Windows binary from the release build's dry run
(the source and the profile-guided recipe the release is built from), with
Node 24.19.0 in the same runs. Both ZIPP binaries run with address-space
randomization turned off and the code cache off, pinned to one core; the
figures are medians of 9 interleaved runs (7 for the three programs timed
separately). Every one of the 90 programs prints the same output under
0.0.35 and 0.0.36 in both lanes.

**The 90 benchmark programs** (the 78 of earlier releases, the seven
bundled applications and five TypeScript benchmarks compiled to
JavaScript). The geometric means are over the 87 programs one pass timed
with all three engines; the other three (the TypeScript bundle, which Node
cannot run, and two ES-module programs) were timed separately and are
given below, and the counts against Node include the two modules.

- **With the JIT:** 0.997x 0.0.35's time, faster on 53 of 87 and by more
  than 2% on 16. The largest gains are `shapes-megamorphic` (0.95x),
  `warm-router`, `collections-map-mixed`, `raytracer` and `shapes-stable`
  (0.96x), and `strings-unicode-scan`, `ephemeral` and `finally-labels`
  (0.97x). Slower by more than 2% in this pass: `lived` (1.08x),
  `dict-churn` (1.06x), `await-sustained` (1.05x), `accessors-proxy` and
  `markdown-render` (1.04x), `dv_get`, `sparse-array-v2`, `misc` and
  `regex-unicode-sticky` (1.03x) and `recursion-shapes` (1.02x). Timed again
  with 15 interleaved runs, six of them are level (0.98x to 1.01x);
  `lived` takes 1.07x, `accessors-proxy` 1.04x, `regex-unicode-sticky`
  1.03x and `misc` 1.02x, and plain builds of the two sources (no
  profile-guided compilation) are level on all four (0.98x to 1.01x): the
  difference is the profile-guided build's layout, not the code.
- **Against Node 24, with the JIT:** 0.602x Node's time, ahead on 70 of the
  89, where 0.0.35 in the same runs takes 0.603x and is ahead on 71.
  `strings-unicode-scan` changed sides to ZIPP; `accessors-proxy` (1.01x)
  and Vue server rendering (1.00x) changed sides to Node by a hair, and in
  the 15-run pass `accessors-proxy` is ahead again (0.99x). Node is still
  ahead on `babel` (3.79x), `class-features` (2.14x), `expr-compiler`
  (2.10x), the eight libraries (1.70x), `recursion-shapes` (1.66x),
  `collections` (1.65x), `generators-iterators` (1.56x), `dataview-binary`
  and `old-to-young` (1.41x), `regex-unicode-sticky` (1.39x),
  `numbers-format-parse` (1.36x), `await-sustained` and
  `destructuring-spread` (1.34x), `large-heap-churn` (1.22x), `raytracer`
  (1.13x), Prettier (1.10x) and `f64_write` (1.05x).
- **Interpreted** (`ZIPP_NOJIT=1 ZIPP_NO_RX_JIT=1`, no native code at all):
  0.984x 0.0.35's time, faster on 50 of 87 and by more than 2% on 18:
  `sparse-array` (0.59x), `dv_get_glob` (0.84x), `typedarray-math`
  (0.85x), `obj_literal` (0.89x), `new_class` (0.90x), `new_obj` and
  `try_catch` (0.92x), `mutators` (0.93x) and ten more by 2 to 4%. Slower
  by more than 2% in this pass: `accessors-proxy`, `proto_read`,
  `preact-ssr`, `class_method` and `survival` (1.04x to 1.05x), `misc`
  (1.03x) and `regex-unicode-sticky` (1.02x). Timed again with 15
  interleaved runs, `proto_read`, Preact and `survival` are level (0.99x
  to 1.01x), `accessors-proxy` takes 1.05x, `regex-unicode-sticky` 1.04x,
  `class_method` 1.03x and `misc` 1.02x; plain builds of the two sources
  take 0.95x, 0.99x and 1.02x on the middle three and 1.03x on `misc`,
  whose small loss is the code's.
- **Against `node --jitless`, interpreted:** 0.759x its time, ahead on 75
  of the 89 programs Node runs, where 0.0.35 in the same runs takes 0.772x
  and is ahead on 70. Five programs changed sides to ZIPP: `sparse-array`,
  `typedarray-math`, `obj_literal`, `dv_get_glob` and
  `strings-unicode-scan`; none changed sides to Node. Node is still ahead
  on `babel` (1.86x), the eight libraries (1.65x), Prettier (1.55x),
  `expr-compiler` (1.43x), `class-features` (1.37x),
  `class-prototype-hot` (1.33x), `destructuring-spread` (1.29x),
  `await-sustained` (1.18x), `old-to-young` (1.14x), `new_obj` and
  `large-heap-churn` (1.13x), `generators-iterators` (1.07x), `new_class`
  (1.04x) and `warm-router` (1.01x).
- **The other three** (medians of 7 runs, a pass of their own): the
  TypeScript bundle, which Node cannot run (its bundled `os` is a stub),
  takes 1.01x 0.0.35's time with the JIT and 1.02x interpreted. The two
  ES-module programs take 1.00x 0.0.35's time with the JIT (`entry`,
  `nanoid-non-secure`) and 0.98x and 0.97x interpreted, and are ahead of
  Node in both lanes: 0.38x and 0.88x Node's time with the JIT, 0.64x and
  0.78x `node --jitless`'s.

## Publishing

As for earlier releases, the engines the site serves are refreshed AFTER this
release exists, in one commit that:

1. sets `zippEngineRelease` in `landing/package.json` to `0.0.36`;
2. refreshes `landing/public/playground-runtime` and `landing/public/wasm` from
   `zipp-0.0.36-javascript-python.wasm` and `zipp-0.0.36-javascript.wasm`
   (`node crates/zipp-wasm/embed-kit/package.mjs extract`, then
   `sync-playground.mjs --refresh-engine`), SHA256SUMS-verified;
3. syncs the sandbox playground (`node landing/scripts/sync-sandbox.mjs` with
   the release's files) and rewrites the site's Brotli copies
   (`npm run compress:engines`);
4. updates the version, size and SHA-256 that `landing/src/App.tsx` and
   `landing/README.md` state about the bundled engine.
